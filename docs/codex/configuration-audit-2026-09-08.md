# Codex: аудит и настройка от 2026-09-08

Проверена локальная установка Codex CLI 0.153.4. Изменения относятся к Linux-роли
и текущему `~/.codex`; Windows/macOS provisioning не изменяется.

## Модели и лимиты

| Запуск | Модель | Reasoning | Назначение |
| --- | --- | --- | --- |
| `codex` / `codex --profile lean` | gpt-5.6-terra | medium | Обычная разработка и отладка |
| `codex --profile deep` | gpt-5.6-sol | high | Сложный анализ и review |
| `codex --profile astra` | gpt-6-astra | medium | Наиболее сложные задачи через несколько этапов |

Terra выбрана пользователем как основная. Astra остаётся доступна отдельным
профилем. По умолчанию ответы краткие, `service_tier = "default"`.
Профили моделей больше не включают memory, sequential-thinking, fetch и
Context7 автоматически. Два документационных MCP остаются включены.

Начинать с одного вспомогательного агента только при наличии независимой задачи.
Настроен предел двух одновременно открытых вспомогательных потоков; основная
ветка в этот предел не входит. Разведка, документация и тесты — Terra; сложное
review и архитектура — Sol/high. Глобальные инструкции запрещают рекурсивное
делегирование и автоматический этап knowledge-curator для каждой задачи.

Это уменьшает необязательные вызовы и контекст, но не обещает определённый процент
экономии: расход зависит от задачи, reasoning, тарифа и активных настроек клиента.
Auto-review тоже выполняет отдельную работу; документация не устанавливает здесь
универсальную стоимость одного рассмотрения.

Официальные основания: [модели](https://developers.openai.com/codex/models),
[настройки](https://learn.chatgpt.com/docs/config-file/config-reference).

## Автономность и правила

Исходный `default.rules`: 896 строк, 236 правил, из них 193 `allow` и 43 `prompt`.
Проверка настоящим `codex execpolicy check` подтверждала безусловный `allow` для
`python3 -c`, `fd --exec`, `git -C /tmp/example push` и `openocd -c shutdown`.
Имя build/test-команды не является ограничением безопасности: Makefile, pytest,
Cargo build scripts и npm scripts могут выполнять произвольный код.

Новая схема:

```toml
sandbox_mode = "workspace-write"
approval_policy = "on-request"
approvals_reviewer = "auto_review"

[apps._default]
approvals_reviewer = "user"
default_tools_approval_mode = "writes"
destructive_enabled = false
open_world_enabled = false
```

Обычные команды выполняются внутри sandbox. При необходимости выхода за границы
автоматический reviewer оценивает конкретное действие и авторизацию пользователя.
`prompt` в rules в таком режиме означает рассмотрение reviewer, а не обязательное
ручное подтверждение. Для app-действий отдельно сохранён reviewer `user`.

Активный `default.rules` сокращён до 25 строк и 8 правил. Глобальные разрешения
для shell, Python, env, timeout, сборок, прошивки и SSH удалены. Единственное глобальное `allow` — чтение списка USB через `lsusb`.
Для привилегированных, опасных Git-, внешних и аппаратных действий оставлены
`prompt`. Эти префиксы не являются исчерпывающей защитой от всех вариантов
аргументов: основная граница — sandbox и автоматическое рассмотрение эскалаций.

Linux provisioning управляет `default.rules` целиком и при повторном запуске
сбрасывает накопленные интерактивные разрешения, сохраняя backup. Отдельные
пользовательские `.rules` остаются активными; их разрешения тоже нужно учитывать.
Backup не должен оканчиваться на `.rules`, иначе Codex загрузит старые разрешения.
Исходный файл содержит команды с буквальными SSH-паролями. Их значения не включены
в этот отчёт или репозиторий; резервные копии нужно хранить с правами `0600`.
Если пароли используются вне изолированного стенда, их следует сменить.

Глобальное разрешение сети и всего домашнего каталога не добавляется. Для повторяющихся
сборок предпочтительны:

- запуск из корня нужного workspace;
- `--add-dir /точный/соседний/репозиторий` для уже авторизованного совместного изменения;
- кэш и временные файлы внутри workspace или `/tmp`;
- конкретный target/board/transport в задаче по аппаратной отладке;
- `workdir` вместо оболочки с `cd`, переменными и длинным `zsh -lc`;
- один осмысленный запрос эскалации вместо добавления новых универсальных префиксов.

Skills и AGENTS.md направляют поведение, но не предоставляют доступ к файлам,
сети или устройствам. `approval_policy = "never"` не предоставляет недостающие
права: операция может просто завершиться ошибкой. Auto-review также может отказать;
при таком отказе агент должен пояснить причину и использовать более безопасное
действие либо запросить недостающую авторизацию. Нулевое число остановок не гарантируется.
Настройки начинают действовать в новых сессиях; текущая сессия сохраняет ограничения,
заданные при запуске или управляемой средой.

Официальные основания: [auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review),
[правила](https://developers.openai.com/codex/rules),
[защищённые пути и sandbox](https://learn.chatgpt.com/docs/agent-approvals-security).

## Skills

Сохраняются предметные навыки C++, Rust, Python, pandas/ML pipelines, SQL, MCP/API,
документации, DevOps, безопасной реализации, PDF, Playwright, Jupyter, CLI,
а также systematic-debugging, verification-before-completion и receiving-code-review.
Пользовательский `mik32-debugging` сохраняется.

Отключаются 10 пересекающихся или узких skills: test-driven-development,
requesting-code-review, writing-skills, karpathy-guidelines, database-optimizer,
security-reviewer, legacy-modernizer, spec-miner, fine-tuning-expert, winui-app.
Причина — обязательные цепочки процедур, дублирование активных навыков либо отсутствие
потребности в повседневной Linux/embedded-разработке. Это выбор стартового набора,
а не утверждение о низком качестве этих skills.

В текущей установке используются `[[skills.config]] enabled = false`, без удаления
исходников. Для повторного включения удалить путь из `codex_disabled_skill_paths`
и вернуть название в соответствующий список установки в `group_vars/all.yml`.
При следующем provisioning исключённые управляемые symlink могут быть удалены;
репозитории источников при этом сохраняются. Системные и plugin skills не редактируются.
Текст сторонних skills не обновляется вслепую из HEAD: в рамках изменения
актуализирован выбор активных skills, а не версии всех внешних репозиториев.

Не установлен искусственно маленький лимит каталога: он может скрыть полезный skill.
Codex использует progressive disclosure: в начальный контекст попадают метаданные,
полный текст читается при применении. Сокращение процедурных skills уменьшает прежде
всего ненужные загрузки и цепочки действий.
[Официальное описание skills](https://developers.openai.com/codex/skills).

## Результат применения

Применены семь файлов в `~/.codex`: `config.toml`, `lean.config.toml`,
`deep.config.toml`, `astra.config.toml`, `config.permissions.example.toml`,
`AGENTS.md`, `rules/default.rules`. Резервная копия:
`~/.codex/backups/config-review-20260908-072120` (каталог `0700`, файлы `0600`).

Реальный `config/read` подтвердил Terra/medium, `auto_review`, `workspace-write`,
два вспомогательных потока и `max_depth = 1`. `skills/list` сообщил об отключении
всех десяти выбранных навыков, без ошибок обнаружения; `mik32-debugging` существует.
Повторное применение подготовленных файлов не изменило состояние.
Изолированный повтор Ansible: `ok=8 changed=0 failed=0`.
Проверена также миграция старого `agents.max_threads` в актуальный параметр.

Полная автономная модельная сессия с внешними операциями не запускалась:
проверены конфигурация, загрузка skills и решения rules, а не гарантированное
одобрение reviewer всех будущих действий. Изменения firstboot оставлены локально,
без commit/push. Репозиторный `AGENTS.md` изменён локально, но исключён существующим
`.gitignore`; воспроизводимый глобальный текст находится в Linux-роли.
